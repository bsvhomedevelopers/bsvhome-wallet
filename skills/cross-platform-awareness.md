# Cross-Platform Awareness

Applies to every task. iOS is the only app target for coding work. Shared Core changes may affect other consumers, but the Android project remains out of scope under [AGENTS.md](../AGENTS.md#ios-only-coding-scope).

## Rules

1. Regenerate and verify iOS when a `core/` change affects UniFFI/TypeShare interfaces, generated models, iOS build inputs, or app-side integration. Run these commands from the repository root:
   ```bash
   just ios generate-models
   just ios generate-core
   just ios build
   ```
   Run only the generation commands relevant to the changed contract. Internal Core implementation changes that preserve these contracts require relevant Core builds and tests, without app generation or builds. Adding a variant to a TypeShare enum that iOS switches over (for example `SwapProvider` or `ChainType`) is an interface change: regenerate the iOS models and handle every exhaustive Swift switch.
2. Report possible non-iOS effects of a shared Core change as unverified. Do not inspect, modify, generate, build, or test the Android project for parity.
3. Never edit generated files directly. Files marked `Generated by typeshare` come from `core/` — change the source, run the relevant iOS generator, and include tracked iOS output. iOS TypeShare models live in `ios/Packages/Primitives/Sources/Generated/`; local ignored UniFFI bindings live in `ios/Packages/BsvHomeCore/Sources/BsvHomeCore/BsvHomeCore.swift` and `ios/Packages/BsvHomeCore/Sources/BsvHomeCoreFFI/include/BsvHomeCoreFFI.h`.
4. Run `just ios localize` when changing localization inputs used by iOS. Hardcoded user-visible strings in iOS are a bug.
5. Read chain capabilities from core's `ChainConfig` (`core/crates/primitives/src/chain_config.rs`). Hand-written per-chain capability lists in iOS code are forbidden — they drift from Core.
