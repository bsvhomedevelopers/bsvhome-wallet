# Core Integration

Use when a task touches `core/`, generated bindings, or files marked `Generated by typeshare`.
The iOS app consumes the shared Rust core through generated Swift bindings.

## Rules

- Read [`../core/AGENTS.md`](../../core/AGENTS.md) before changing Rust code or generated interfaces
- Run `just ios generate-core` from the repo root when Rust-to-Swift bindings or iOS Rust static libraries need to be regenerated
- Run `just ios run` from the repo root to build and run the iOS app
- The optional `BsvHomeWithCore` Xcode scheme combines cached BsvHomeCore generation with the normal app build
- Run `just ios generate-models` from the repo root when shared model or remote mapper generation is required
- Apply [Cross-Platform Awareness](../../skills/cross-platform-awareness.md) for generation and app verification; internal Core implementation changes that preserve mobile contracts need Core checks only

## Generated Files

- Files marked `Generated by typeshare` are generated and will be overwritten
- Never edit generated files directly
- Add Swift extensions in separate files, typically under the relevant `Extensions/` directory

## Integration Notes

- `BsvHomeCoreFFI` is a source C target that exposes the UniFFI header to SwiftPM
- The BsvHomeCore UniFFI Swift/header sources are generated locally and are not committed
- BsvHomeCore generation also builds the iOS `libbsv_home_core.a` outputs under `core/target`; the app links those outputs directly
- The normal `BsvHome` scheme expects generated bindings and Rust static libraries to already exist
