# Offline identity factor

`OfflineIdentityScene(model:)` is a full-page navigation flow opened from the cold wallet device root in `BsvHome`. Construct `OfflineIdentityViewModel(keychain:authenticate:)` with the cold wallet Keychain namespace and local authentication service, then present it as a full-screen cover. The daily device handles public key and proof import through its platform account flow.

The independent software P-256 identity is stored as one device-bound, non-synchronizing Keychain item. A protected, backup-excluded file lock serializes identity creation and import across instances and processes. Existing or damaged identity state is never automatically overwritten. Backgrounding, capture notifications, protected-data loss and feature lifetime end clear passwords and in-progress challenge/export state; iOS screenshots cannot be guaranteed to be blocked.

Public keys are canonical P-256 SPKI DER/Base64URL; backup private keys are PKCS8 DER/Base64URL. Only an encrypted backup reaches the file exporter. It uses PBKDF2-HMAC-SHA256 with 310000 iterations, a random 16-byte salt, AES-256-GCM with a random 12-byte nonce and `WowPay/OfflineIdentity/backup/v1` AAD. Password bytes use UTF-8 without normalization. The complete ciphertext includes the GCM tag. The recovery format is separate from MPC A backups and HD wallet secrets.

A generated identity cannot export its public key or sign a challenge until the system file exporter reports that the encrypted backup was saved. Importing an existing authenticated backup validates the recovered public/private key pair and retains that backup status. Cancelling or receiving a stale save callback does not change backup status.

`BsvHomeOfflineIdentityService` owns the public document shape, limits, canonical Base64URL, fingerprint, purpose and challenge association rules. The challenge review displays account, purpose, label, fingerprint, action digest and the original expiry text. Offset timestamps and local timestamps retain their original meaning; the offline tool does not claim to validate the server's complete business request from a digest or to replace the online service's expiry checks. CryptoKit signs the UTF-8 actionHash text with ECDSA/SHA-256, verifies it locally and exports only the linked public proof.

The Swift `OfflineIdentityTests` target includes an independent Python hashlib/cryptography interoperability vector covering Unicode password encoding, PBKDF2, AES-GCM/AAD, PKCS8/SPKI and DER signatures, plus tampering, missing-backup, overwrite, cancelled-save and stale-callback rejection. Fixture keys are synthetic public test material. Run the target in the `BsvHome` test plan with `just ios test OfflineIdentityTests`. Core rules run with `cd core && cargo test -p gemstone --lib services::offline_identity`.
