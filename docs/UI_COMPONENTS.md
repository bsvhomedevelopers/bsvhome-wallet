# UI Component Inventory

Read this inventory before UI work, then read the selected component and its actual caller. Reuse first, extend second, add only when an existing owner cannot serve the requirement. Update this file in the same change as component API or ownership changes. Global discovery lives here; each entry explicitly identifies its platform. The current audited scope is iOS, not an assertion that Android has no equivalent components.

`Existing` means present in source; it does not mean verified against WowPay. `Planned` means not yet a callable implementation. `Implemented` means source is integrated; build and runtime verification are tracked separately in [the migration checklist](WOWPAY_UI_REFACTOR.md). Visual values come from [UI Style Tokens](UI_STYLE_TOKENS.md).

## Existing iOS Components

### BsvHome brand resources — 2026-11-17

The current BsvHome chain-link artwork is `ios/BsvHome/Resources/Images.xcassets/wowpay-mark.imageset/wowpay-mark.png`; the retained asset name also serves the existing Home and welcome consumers. `AppIcon.appiconset` derives its light, dark and monochrome tinted icons from this mark. The App's `bsvhome-launch-logo.imageset` supplies the light/dark BsvHome wordmark at 1x/2x/3x to `Info.plist` → `UILaunchScreen`. The separate `Style` catalog's `logo` and `logo-dark` images supply the same chain-link mark at 120 pt to `Images.Logo`, including `Components/LogoView` → `LockManager/LockScreenScene`, so the startup handoff does not restore the older WowPay W. Existing appearance backgrounds and component APIs are retained.

### WowPay typography owner

[WowPayFont](../ios/Packages/Style/Sources/WowPay/WowPayFont.swift) extends the existing Style family rather than introducing a new typography package. Its native/scaled variants preserve retained SwiftUI fonts and resolve WowPay roles with environment-aware `ScaledMetric` on iOS 17 and later. `.font(.wowPay.role)` supports optional font inputs and weight chaining. `TextStyle` retains its native-Font initializer and carries this same variant through row, button and transaction renderers. The existing amount editor resolves its font and fixed UIKit line-height frame from the same role size and scaling style. Default point sizes and native semantic multisig curves remain unchanged; runtime and visual acceptance are recorded separately.
